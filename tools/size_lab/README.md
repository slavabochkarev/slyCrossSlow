# КроссСлов: проверка реального Game Screen

Это временный developer/test режим для определения комфортного размера Crossword. Он использует **те же** `GameScreen`, `CrosswordBoard`, `LetterBoard`, header, current-word area, Hint и Shuffle, что и игра. Все буквы кроссворда открыты только в этом режиме, чтобы оценить читаемость. Игровая механика, progression, `assets/levels.json` и генератор не менялись.

## Открыть и перелистывать

Из корня проекта на установленной Flutter desktop/web-среде:

```powershell
flutter run -d windows -t lib/dev/crossword_size_lab.dart
```

Нажмите центральную плашку `6×6 ›` в header для следующей сетки; кнопку назад — для предыдущей. Последняя сетка возвращает к первой. Режим пишет в консоль строку с grid, доступной областью, размером клетки, размером сетки и статусом комфорта. Основная точка входа `lib/main.dart` этот режим не открывает.

Семь зафиксированных уровней находятся в `lib/dev/size_lab_levels.dart`:

| Сетка | Основа | Слов | Источник |
| --- | --- | ---: | --- |
| 6×6 | ЛОСКУТ | 7 | второй POC |
| 7×7 | КРАСОТА | 8 | второй POC |
| 8×8 | РОДИНКА | 9 | второй POC |
| 10×10 | ОРКЕСТР | 14 | запуск прежнего `generator.py` с `--max-words 14 --max-span 10`, сохранён в `tools/level_generator/size_lab_search/` |
| 7×8 | РОСТОК | 8 | сохранённый вариант второго POC на 8 слов |
| 8×9 | ОСТАНКИ | 14 | сохранённый результат прежнего `generator.py` |
| 8×10 | ОТПРЫСК | 14 | сохранённый результат прежнего `generator.py` |

`tools/size_lab/export_fixtures.py` повторно создаёт Dart fixtures из соответствующих JSON. Production-уровни в нём не используются.

## Методика

В `CrosswordBoard` клетка остаётся квадратной и максимально возможной в области, которую `GameScreen` выделил после header и controls:

```text
cell = min(74, (available_width − 24) / columns,
               (available_height − 24) / rows)
```

24 px — внутренние поля board по 12 px с каждой стороны. Нарисованная клетка имеет сторону `cell − 4`, текст открытой буквы — `cell × 0.54`. Порог **36 px** для `cell` принят как временная граница комфортного просмотра: ниже этого получается менее 32 px нарисованной клетки и менее 19.5 px текста. Превышение порога выводится в диагностике; LetterBoard и кнопки ради кроссворда не уменьшаются. Сам кроссворд всё же рисуется в доступной области, чтобы его можно было сравнить визуально.

Widget-тесты задают логические размеры 360×800, 390×844, 412×915, 1024×768, 1200×800. Для телефонов дополнительно учтены safe area по 24 px сверху и снизу; для wide — нулевые insets. Каждый PNG в `screenshots/` показывает **полный Game Screen**, а не отдельный preview сетки. Тесты проверяют отсутствие overflow и scrolling, порядок header → Crossword → current word → LetterBoard с кнопками по его бокам, сохранение размеров controls и навигацию developer-режима. Скриншоты сняты со шрифтами Flutter и фоновым изображением.

## Визуальный вывод

На всех трёх портретных экранах 6×6 и 7×7 имеют большой запас; 8×8 остаётся читаемым и не прижимается к header. Текущему слову и LetterBoard остаётся место, кнопки не меняют размер, scrolling не появляется. На 360×800 сетка 10×10 с клеткой 31.2 выглядит заметно мельче; на 390×844 клетка 34.2 всё ещё ниже принятого порога. На 412×915 она даёт 36.4 и проходит лишь с небольшим запасом. На wide 10×10 читается свободно.

Практический общий лимит для перечисленных телефонов при пороге 36 px — **ширина до 8, высота до 9 клеток**. Сетка 8×9 на 360×800 даёт 37.1 px; 8×10 даёт только 33.4 px и потому не допускается в новом эксперименте генератора. Порог 36 px и снимки эмуляции логического экрана не заменяют проверку физического размера, плотности дисплея и удобства касаний на настоящих телефонах.

## Проверить повторно

```powershell
flutter analyze lib/dev/crossword_size_lab.dart lib/features/game/widgets/crossword_layout.dart test/crossword_size_lab_test.dart
flutter test test/crossword_size_lab_test.dart --reporter expanded
```

Тест сохраняет 35 PNG в `tools/size_lab/screenshots/` и выводит диагностику для каждого сочетания размера экрана и сетки.
