# КроссСлов: словарь и генератор уровней

Инструмент запускается вне Flutter. `dictionary.py` обновляет `data/words.txt` и runtime-файл `assets/game_words.txt`; генератор сохраняет эксперименты в `tools/level_generator/`. Файлы preview предназначены для ручной оценки и сами не меняют `assets/levels.json`. Текущая production-кампания содержит 150 уровней, а Endless повторно использует кроссворды уровней 50–150 без генерации новых.

## Подготовка словаря

Pipeline: исходные строки → нормализация → `data/raw_words.txt` → пересечение с игровым отбором → `data/words.txt` и `assets/game_words.txt` для Flutter. Один ряд — одно слово. Исходные снимки остаются нетронутыми. `data/exclude.txt` — постоянный запрет игрового слоя, применяемый после `data/include.txt` и при загрузке слов генератором. После изменения списков запустите `python dictionary.py`; он обновляет оба игровых снимка.

Нормализация: удаляется только пробел **по краям**, слово переводится в uppercase, `Ё` заменяется на `Е`. `Й` сохраняется отдельной буквой. Внутренние пробелы, дефисы, цифры, латиница, сокращения с пунктуацией и слова вне длины 3–7 отклоняются целиком; символы из них не склеиваются. В «Пятибукв» при проверке ввода дополнительно применяется `Й→И`, но здесь это преобразование не применяется, чтобы не смешивать разные буквенные наборы. `Ё→Е` может объединить омографы; это ограничение POC и повод для ручной проверки до интеграции.

Обнаружить все имена собственные или редкие термины без размеченного корпуса невозможно. Пересечение с меньшим списком и ручной `exclude.txt` снижают их число. Пятибуквенный `acceptedWords` содержит 3470 записей по фактическому файлу (в README «Пятибукв» указано 3473); для игрового отбора используются 423 `answerWords`.

## Генерация

`Letter Set` — отсортированный **мультимножество** букв длиной 6 или 7. Каждый seed — игровое слово той же длины; несколько seed с одним canonical key рассматриваются как один набор. Word Potential — все игровые слова длиной 3–7, чей `Counter(word)` является подмножеством `Counter(letters)`, включая кратности букв. Наборы с потенциалом меньше 8 и с менее чем 3 словами длины 4–6 отсекаются. Дальше берутся лучшие наборы по экспериментальному рейтингу потенциала и несколько раз строится сетка.

Поиск начинается с seed и добавляет случайно выбранный вариант из пяти лучших допустимых размещений. Новое слово обязано пересечь уже размещённые; несовпадающие буквы, параллельное наложение, боковое касание, касание за концом слова и более одного пересечения пары запрещены. В результате граф слов связен. Границы вычисляются по занятым клеткам, пустая внешняя рамка не сохраняется. Ограничены число letter sets, число попыток для каждого, размер сетки и число слов.

Итоговый score (коэффициенты в `scoring.py`, экспериментальные):

```text
100 × words + 24 × square + 20 × density + 9 × crossings
+ 3 × sum(max(word_length − 3, 0))
− 1.5 × bounding_box_area − 4 × one_crossing_words
− 3 × (width − height)²
```

`square = min(width,height)/max(width,height)`, `density = occupied/(width×height)`. Количество слов доминирует, размер и «усы» штрафуются. Словарь уже является фильтром качества; отдельного балла «частотности» нет. На POC максимум 11 размещённых слов — параметр поиска, а не правило игры.

## Запуск

Нужен Python 3.10+ без сторонних пакетов. Из корня проекта:

```powershell
python tools/level_generator/generator.py --seed 42
python tools/level_generator/test_generator.py
```

Для обновления пятибуквенных снимков из локального проекта:

```powershell
python tools/level_generator/import_pyatibukv.py --source C:\Project\Pyatibukv\lib\word_dictionary.dart
```

Параметры: `--set-limit 32`, `--attempts 12`, `--max-words 11`, `--max-span 11`, `--top 10`, `--output <directory>`, `--seed 42`. Одинаковые исходные снимки, overrides, параметры и seed дают одинаковый результат. `set-limit` ограничивает число богатых наборов, `attempts` — варианты для набора, `max-span` — ширину и высоту. Это конечный ограниченный поиск, а не гарантия глобального оптимума.

Результаты: `output/generator_output.txt` (полные списки и сетки с `·`), `output/preview.html` (самостоятельная HTML-страница с выделенными пересечениями), `output/candidates.json` (данные для анализа). Ничего из `output/` автоматически не попадает в Flutter.

## Ограничения перед внедрением

- Даже опубликованный список «распространённых» содержит спорные и редкие слова; `exclude.txt` содержит постоянные исключения, включая выявленные pluralia tantum, но всем кандидатам нужна редакторская оценка.
- Пятибуквенные игровые слова ограничены 423 словами для ответов «Пятибукв», поэтому возможные комбинации длины 5 неполны.
- Рейтинг может предпочесть множество коротких трёхбуквенных слов и повторять их между уровнями. Нет оценки разнообразия слов в серии и нет настоящей частотности.
- Жадный поиск с ограниченными попытками может пропустить более плотную сетку; `max-span` и `max-words` могут отсечь допустимые варианты.
- Имена собственные и обидные слова не исключаются автоматически с гарантией. Перед выпуском нужен ручной список, а при необходимости — словарь с пометами и проверенной частотностью.

## Эксперимент с физическим лимитом Game Screen

`experiment_physical.py` — отдельный третий эксперимент. Прежние `generator.py`, `scoring.py`, POC и их результаты остаются доступными. Эксперимент не записывает уровни во Flutter. Размеры измерены в полном Game Screen через `tools/size_lab/`: при 360×800 клетка 8×9 равна **37.1 px**, 8×10 — **33.4 px**. При пороге 36 px здесь разрешены сетки до **8 клеток по ширине и 9 по высоте**. Для 390×844 и 412×915 клетка 8×9 составляет 42.0 и 45.5 px.

Поиск рассматривает 40 наборов каждой длины и 12 попыток для набора, сохраняя лучший вариант на каждое достигнутое число слов от 6 до 14. Слова из `data/questionable_words.txt` исключаются до поиска. Для ограничения коротких заполнителей допускается не более четырёх трёхбуквенных слов, а для семибуквенного Letter Set — не более двух семибуквенных слов. Это экспериментальный критерий качества, не частотная оценка и не редакторское одобрение слов. Правило не более одного пересечения каждой пары слов сохранено в общем `crossword.can_place`.

Оценка только для прошедших словарный и физический фильтры:

```text
100 × used + quality + 6 × crossings + 20 × density
− 0.55 × area − 5 × one-crossing words + 2 × square
quality = 12 × five-letter + 8 × six/seven-letter + 4 × four-letter
```

Квадратность даёт максимум два балла и не имеет бонуса за точное значение 1.0. Количество слов преобладает после фильтра качества; пересечения, плотность, компактность и ветви решают близкие варианты. Поиск ограничен и не доказывает глобальный оптимум.

```powershell
python tools/level_generator/experiment_physical.py --set-limit 40 --attempts 12
```

Новые файлы: `experiment_physical_output/preview.html` (TOP-10 + TOP-10 по итоговому score), `candidates.json` (все слова и метрики), `per_count_best.json` (лучший найденный вариант каждого количества слов), `rectangular_examples.json` и `generator_output.txt`. HTML отдельно показывает лучшие найденные варианты 6×7, 7×8, 8×9. Сравнение с прежним POC описательное: поменялись и поиск, и ограничения, поэтому разницу нельзя приписывать одному лишь scoring.

Текущий прогон нашёл, например, ЛОСКУТ 6×7 с 9 словами против прежнего 6×6 с 7, а ОКРАСКА 8×9 с 13 словами против прежнего 8×8 с 10. Обе сетки укладываются в физический лимит. TOP-20 проверены на связность, единственность пересечения пары, лимиты размеров, количество слов и исключённые пометки. Перед использованием в игре нужен просмотр слов человеком.
